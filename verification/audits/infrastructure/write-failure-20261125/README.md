# Issue-body write read-back failure of 2026-11-25 (evidence)

Evidence kept under AGENTS.md §A.49 rule 3 and §A.26. Nothing here is adopted or normalized; the
stored Issue bodies are left as they are.

## What happened

On 2026-11-25 the coordinating session edited the planning-status blocks of five Issues with
`gh api -X PATCH repos/amaybaum/incompleteness/issues/{n}` (body field), recording owner decisions
quoted at #1169 comment 7164587230 and on each Issue. Each write was read back and compared byte for
byte with the text sent (`readback.json`).

| Issue | Stored equals sent | Stored equals sent + footer | Pre-edit body ended with footer |
|---|---|---|---|
| #1558 | no | yes | no |
| #1062 | no | yes | no |
| #1245 | no | yes | no |
| #1556 | no | yes | no |
| #1565 | yes | no | yes |

In the four mismatches the only difference is a trailing attribution footer
(`\n\n---\n_Generated by [Claude Code](https://claude.ai/code)_`) present in the stored text and
absent from the text sent. #1565, whose body already ended with that footer, was stored unchanged.
Issue-body edits through the REST API had not been validated as an operation before these writes.

## Two defects

1. **Text changed before storage.** Something between the session and GitHub appends the footer to an
   Issue body sent without one. Its source is not established.
2. **No stop on the first mismatch.** `edit.py` printed the read-back result and continued, so after
   the mismatch on #1558 it wrote #1565, #1062, #1245 and #1556, and changed labels. §A.49 rule 3
   requires automated text writes to stop at once.

Automated GitHub text writes stopped when the mismatches were found and remain stopped.
