# Issue-body write read-back failure of 2026-11-25 (evidence)

Evidence kept under AGENTS.md §A.49 rule 3 and §A.26. Nothing here is adopted or normalized; the
stored Issue bodies are left as they are.

## What happened

On 2026-11-25 the coordinating session edited the planning-status blocks of five Issues with
`gh api -X PATCH repos/amaybaum/incompleteness/issues/{n}` (body field), recording owner decisions
quoted at #1169 comment 7164587230 and on each Issue. Each write was read back and compared byte for
byte with the text sent (`readback.json`).

| Issue | Stored equals sent | Stored equals sent + footer | Pre-edit body ended with footer |
|---|---|---|---|
| #1558 | no | yes | no |
| #1062 | no | yes | no |
| #1245 | no | yes | no |
| #1556 | no | yes | no |
| #1565 | yes | no | yes |

In the four mismatches the only difference is a trailing attribution footer
(`\n\n---\n_Generated by [Claude Code](https://claude.ai/code)_`) present in the stored text and
absent from the text sent. #1565, whose body already ended with that footer, was stored unchanged.
Issue-body edits through the REST API had not been validated as an operation before these writes.

## Two defects

1. **Text changed before storage.** Something between the session and GitHub appends the footer to an
   Issue body sent without one. Its source is not established.
2. **No stop on the first mismatch.** `edit.py` printed the read-back result and continued, so after
   the mismatch on #1558 it wrote #1565, #1062, #1245 and #1556, and changed labels. §A.49 rule 3
   requires automated text writes to stop at once.

Automated GitHub text writes stopped when the mismatches were found and remain stopped.

## Investigation and write-safety protocol

`write-safety/PROTOCOL.md` states the findings and the proposed correction. In brief:

- **Text changed before storage.** The rule that fits all five writes is "append the footer when the
  body does not already end with it". `gh` and the local Claude Code configuration are ruled out by
  inspection; the egress proxy, which terminates TLS for `api.github.com` and adds the GitHub
  credential, is the most likely locus; GitHub itself is unlikely. No write from this environment
  can distinguish the proxy from GitHub.
- **No stop on the first mismatch.** `edit.py` printed its verdict and continued; replayed against a
  mock transport it makes 10 writes, 9 after the first mismatch. A related shell sequence the same
  day pushed with an empty commit id, which is a ref-deletion request (the ref did not exist; nothing
  changed). Both are write steps that are not fail-closed.
- **Correction.** One gate (`gate.py`) for every automated text write, label or state change and
  push: a persistent halt marker checked before any request, an expected stored text fixed before
  the write and compared byte for byte, an immediate halt on any mismatch, failed read-back,
  unexpected status or exception, and refusal of malformed commit ids and of ref deletions.

**Controls** (mock transport only): run `python3 -I -B test_gate.py` and
`python3 -I -B countercontrol.py` in `write-safety/` (`ev` is a link to this directory). Expected: 14
of 14 tests pass; countercontrols C1, C2 and C3 pass (`edit.py` makes 9 writes after the mismatch and
the gate 1; the deletion refspec is refused; mutated gates fail the tests). Recorded results:
`results-tests.txt`, `results-countercontrol.json`. The survey files list, for comments and Issue or
pull-request bodies written through the two GitHub Apps on the repository, the date, the App and
whether the text ends with the footer.

in the footer with three newlines before `---`; resent with only a new planning block added, it was

## Revised gate v2: bounded transport-difference policy (for review, not adopted)

Owner decision recorded at #1548 comment 7166079053, with clarifications at #1169 comment
7166129327. `write-safety/PROTOCOL-v2.md` states the policy. `transport_rules.py` holds a closed,
frozen registry of permitted transport transformations, with one entry, `footer-attribution-1`
version 1: in a body only, the exact attribution footer at the very end of the stored text, with
only the number of newlines before it (at least two) and after it differing; spaces, tabs and every
other character, including Markdown hard line breaks and indentation, are compared exactly.
`gate2.py` (built on `gate.py`, with no footer text of its own) accepts an exact match, accepts a
difference permitted by exactly one listed rule with a record (both full texts, digests, the diff,
the rule id and version), and otherwise halts (revision r2 below sets the containment). Controls: `test_gate2.py`
(39 tests, including about 120 negative cases for scientific content, links, internal whitespace,
Markdown structure and authorization records) and `countercontrol2.py` (C1-C3: the exact-only gate
rejects the real #1505 and #1558 pairs that gate2 permits; loosened rules and a gate accepting
rejected outcomes fail the controls). Recorded results: 39 of 39; C1-C3 pass; the original suite
(18 of 18) is unchanged. The existing gate stays in use until the owner approves v2 after
independent review and a controlled validation write.

## Gate v2 revision r2: run-level and operation-level containment (for review, not adopted)

Owner decision recorded at #1169 comment 7166845267, with the owner's distinction between run-level
containment (after a mismatch the current write sequence stops completely; catching the exception
allows no further write) and operation-level containment (later independent operations may continue
through validated mechanisms if the evidence supports isolating the defect). Revision r2 follows the
independent review at PR #1566 comment 7166798215 (`write-safety/CHANGES-r2.md` maps each finding).
`gate2.py` now latches: after any halt or exception during a write or push, every gate in the process
refuses every further write and push. It writes the global halt marker for every failure unless all
of four mechanically decided conditions hold (outcome known; read-back complete with no unsent-field,
label or state failure; every rejected difference confined to the trailing tail after the sent
content; no other operation's mismatch outstanding), in which case only the failed operation is
halted, and a later sequence writes nothing until the owner has been told (`HALT.<op>.notified`).
Discrepancy records are written only after a write passes in full; the halt marker embeds the
evidence texts. Recorded results: `test_gate2.py` 49 of 49; `countercontrol2.py` C1-C3 pass (a gate
without the run-level latch fails 3 tests; r1's operation-only containment fails 25); the original
suite is unchanged (18 of 18). The existing gate stays in use until the owner approves v2.
