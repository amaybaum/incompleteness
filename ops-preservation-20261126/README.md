# Coordination tools and incident evidence (preservation branch)

This branch preserves the GitHub writing tools and incident evidence that the coordinating session used on 2026-11-26. It is preserved so that another session (Claude or Codex) can recover the tools without rebuilding them. Owner decision: #1169 comment 7190566162, item 2.

**Not for `main`.** Do not merge this branch. Preserving the tools does not establish that a different execution environment satisfies their validation requirements. AGENTS.md §A.49 (exact read-back, stop on mismatch) and §A.51 item 2 (validated write operations) still govern every write.

## Contents

- `tools/post.py` posts an Issue or PR comment.
  - It refuses before sending: an at-sign, a carriage return, a Cf or non-ASCII space character, a long `blob`/`tree` link without a fragment, a first line beginning with `oi-`, or a `<` immediately followed by `!`.
  - It requires the exact footer boundary (`fcheck.py`).
  - It checks for an identical existing comment, posts, then reads the comment back byte for byte.
  - On any failure or mismatch it writes a halt marker and stops.
- `tools/fcheck.py` checks the footer boundary. The text must end with exactly one blank line, `---`, and the footer line `_Generated by [Claude Code](https://claude.ai/code)_`, with no trailing newline.
- `tools/controls/footer_controls.py` holds 3 positive cases, 9 negative cases, and end-to-end refusal tests run with the network unreachable. `footer_controls.out` is the passing output (30 of 30).
- `tools/mkpr.py` opens a draft PR and `tools/mkissue.py` opens an Issue. Both apply the same prechecks and read back title and body.
- `tools/buildreview.py` builds a verbatim reviewer comment from a subagent's hand-back, with its SHA-256 and redaction header. `tools/atfix.py` applies the disclosed at-sign rewrite.
- `tools/extract_plan.py` extracts a fenced file text from a subagent's hand-back.
- `gate-v2/` is the gate v2 writer for `issue.edit_body`:
  - `gate.py`, `gate2.py`, `transport_rules.py`: the gate itself, with the permitted transport rule `footer-attribution-1`;
  - `registry-v2.json`: the validated-operation registry and its owner decision;
  - `runb.py`: the runner template.
  - `records/` holds the gate logs and discrepancy records of the runs made on 2026-11-26.
- `evidence/pr1591-footer-20261126/` is the incident evidence for the PR #1591 footer read-back mismatch, with its own `MANIFEST.sha256`. It holds the sent and stored texts, the original halt marker, the tools before the correction, the corrected check and its controls. The decision that resumed writing is #1169 comment 7187418279.
- `evidence/poster-halt-20261126/` is the evidence for the earlier poster precheck halt, in which nothing was sent.

## Reproducing operation

1. Requirements: Python 3, and the `gh` CLI authenticated for the repository. No credential is stored here.
2. The scripts contain the coordinating session's scratchpad paths, `/tmp/claude-0/...`. Replace them with local paths before use:
   - `HALT`, which `POST_HALT` overrides;
   - the `sys.path` insert for `fcheck`;
   - `buildreview.py`'s task directory.
3. Run the controls first, and stop unless they print `RESULT ALL PASS`:
   ```
   python3 -I tools/controls/footer_controls.py <dir containing the tools>
   ```
4. Post a comment with `python3 -I tools/post.py <issue-or-pr-number> <body.md>`. The body must already end with the footer boundary.
5. Edit a body through gate v2: copy `gate-v2/` to a fresh directory with an empty `halt/` subdirectory, write `<n>.before2.md` and `<n>.after2.md`, set `B` and a new `pid` in `runb.py`, then run it. A plan id is used once only.
6. Any refusal before sending sends nothing. Any halt stops all automated text writes until the owner decides otherwise (§A.49 rule 3).

`MANIFEST.sha256` lists the SHA-256 of every file on this branch except itself.
